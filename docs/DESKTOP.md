# The desktop application

The desktop build exists so that a business can install ChatCloser the way it
installs any other program: no terminal, no service manager, no port forwarding.
It is not a separate product — it starts the same admin panel and the same
WhatsApp assistant that `npm start` does, inside one process, and shows the
panel in a window.

```
electron-app/
  src/electron/main.js      main process: backend lifecycle, window, tray, IPC, logging
  src/preload.cjs           the only bridge between the page and the main process
  src/assets/icon.png|ico   generated by `npm run icon`
  scripts/prepare-backend.mjs  stages the repository backend into electron-app/backend
  package.json              electron-builder configuration
```

## What happens on launch

1. `main.js` points `CHATCLOSER_DATA_DIR` at the OS user-data folder.
2. `secrets.json` is created on first run: `ENCRYPTION_KEY`, `SESSION_SECRET`
   and an administrator password (random, 12 characters). File mode `0600`.
3. The dashboard is imported with `CHATCLOSER_NO_LISTEN=1` and bound explicitly
   to `127.0.0.1:3001` — never to a public interface.
4. `index.js` starts the WhatsApp socket and the control API (also loopback).
5. A window opens at `http://127.0.0.1:3001/login`; on a first run a dialog shows
   the generated credentials once.
6. The tray icon keeps the application alive when the window is closed, so the
   assistant keeps answering. *Quit* in the tray menu is the way out.

A second launch focuses the existing window instead of starting a second copy
(single-instance lock).

## Security posture

| Control | Setting |
| --- | --- |
| Renderer isolation | `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true` |
| Preload surface | five methods on `window.chatcloser`: `info`, `status`, `restartBot`, `openExternal`, `revealDataFolder` |
| Navigation | locked to `http://127.0.0.1:<port>`; anything else opens in the system browser |
| New windows / webviews | denied |
| Permissions | every `setPermissionRequestHandler` request is denied |
| Opening links | only `https:` URLs, and only in the system browser |
| Secrets | `secrets.json` in the user-data folder; never sent to the renderer |

The page itself comes from the local dashboard, which sets its own Content
Security Policy with per-response nonces. The window is created only after the
port has been bound, so a process that squats on port 3001 before launch causes
a startup error instead of the app showing foreign content.

## Logs and diagnostics

`desktop.log` in the data folder, one line per event, plus the error dialog text
when startup fails. Tray → *Open data folder* reveals it.

## Smoke test

Useful in CI and after changing the shell:

```bash
# headless: start everything, check the panel answers, write a result file
CHATCLOSER_DESKTOP_SMOKE=1 CHATCLOSER_SMOKE_OUT=result.json electron .

# with a window: capture the login page, sign in, capture pages
CHATCLOSER_DESKTOP_SMOKE=2 \
CHATCLOSER_SMOKE_USER=admin \
CHATCLOSER_SMOKE_PASSWORD=... \
CHATCLOSER_SMOKE_PAGES="/overview,/orders,/settings" \
CHATCLOSER_SMOKE_OUT=result.json electron .
```

The result file reports the HTTP status, whether the preload bridge is present,
and whether Node is reachable from the renderer (it must be `false`).

## Not done in the desktop build

- No auto-update channel. Installers are versioned; upgrade by installing over
  the previous version — the data folder is untouched.
- No code signing certificate is included. Windows SmartScreen will warn until
  you sign the installer with your own certificate (`CSC_LINK` and
  `CSC_KEY_PASSWORD` for electron-builder).
- The packaged app manages one workspace. The database and API are multi-tenant,
  but the desktop shell does not offer a workspace switcher.
