01 What it does

A whole business, run from one console

Every module exists on day one — not a bolt-on plugin.

Conversation

Every WhatsApp message becomes a thread on a customer record. The assistant detects Nepali, romanised Nepali and English — and replies in the customer's own language.

Selling

Searches the catalogue, checks stock, quotes a total with real tax and delivery, and hands over a summary. An order exists only after the customer says yes.

Verified payments

eSewa, Khalti, Stripe and manual bank QR. paid is set only by a signed webhook or a server-side lookup — never by a link click or a redirect.

Inventory

Stock movements with reservations, variants, price lists and low-stock alerts. Prices always come from the catalogue — never from the model's text.

Automation Studio

Triggers, conditions, actions, retries and a dead-letter queue. Actions are an allow-list — workflows cannot execute arbitrary code.

Business intelligence

Sales trend, funnel, AI usage and cost, accounting summary. The forecast refuses to guess when there is no history.

Bookings & documents

Appointments with resources, quotations and invoices as printable documents with numbering, plus expense tracking.

Team & audit

Staff accounts with roles and per-permission overrides, approval queues for anything sensitive, and an audit log of every privileged action.

02 The safety design

An AI you can actually trust with your store

These are not features — they are invariants the code enforces, asserted by the test suite.

01

No order without a yes

confirmDraft() refuses to run unless the customer explicitly approved it.

02

Prices never come from the model

Totals are recomputed server-side from catalogue rows on every quote.

03

"Paid" only from the provider

Verified webhook signatures or server-side status calls, deduplicated by event id.

04

Fixed AI role

The assistant's role comes from your business config — a prompt injection can't elevate it.

05

CSRF & escaping everywhere

Double-submit tokens rotated on sign-in; customer text is never rendered as HTML.

06

Encrypted secrets

Provider keys are AES-256-GCM encrypted before they ever touch the database.

04 Get started

Free to run. Yours in ten minutes.

MIT licence. No accounts, no metered services — the only optional paid thing is an external AI key, and Ollama makes even that optional.

1 Server

# Node.js 22.13 or newer
npm install
cp .env.example .env

# fill in ENCRYPTION_KEY & SESSION_SECRET:
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

npm start
# → http://127.0.0.1:3001

2 Desktop app

npm install
npm --prefix electron-app install

# Windows · macOS · Linux
npm run desktop:dist:win

# No .env needed — the shell generates
# its secrets on first launch.

3 Connect & go

# In the console:
1. Settings  → name, currency, tax
2. AI Config → pick a provider
3. WhatsApp  → scan the QR code
4. Payments  → sandbox keys first

First run prints a generated owner password once, to first-run-credentials.txt. Change it and delete the file.
